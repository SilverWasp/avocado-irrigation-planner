Irrigation planning

Avocado Irrigation Planner

Pick any spot on the map. It pulls that location's soil and this week's real hourly forecast, and turns it into a day-by-day, hour-by-hour watering plan — liters per tree, kept inside your water budget and pump, biased to water a little less rather than risk root rot. Everything it pulls automatically, you can also override by hand.

Mode

Fixed, offline demonstration: exactly 2 hot / 1 rainy / 4 normal days, dated to this week's Sunday. Live forecast is disabled here on purpose — the brief it comes from is never meant to be silently replaced by real weather. Switch to Field planning for a real dated week with live data.

How the numbers are built. Each day's water need starts from ET0 (reference evapotranspiration) pulled live from Open-Meteo, which Open-Meteo itself derives from real temperature (not just a daily max — the actual curve), solar radiation (so a cloudy, overcast day pulls this down on its own, with no separate "cloud cover" step needed), humidity and wind. That single figure, scaled by the chosen variety's crop coefficient (Guatemalan types like Reed run higher than Mexican-race types like Bacon or Zutano) and by how well the soil at the pin holds moisture, is this plan's actual water need for the day. Only when no live pull has happened for a given day does it fall back to the hand-set baseline L/tree figure and a coarser hot/normal guess. Real rainfall for that day is converted to liters per tree using the plot's own tree spacing and subtracted in full before anything is irrigated — if rain already covers the need, that day is skipped outright rather than topped up, because under-watering is recoverable and over-watering risks root rot. Every final number is rounded down, never up, for the same reason. If the week's demand still exceeds the water budget, every irrigation day is scaled down proportionally.

Tree density vs. plot size. A single tree's own demand is set by its canopy, not by how much empty land happens to be around it, so each tree's land/water credit is capped at roughly a closed-canopy reference (40 trees/dunam — the default). Planted sparser than that, every tree still gets that full reference share and rainfall is credited the same way, so the plot's total use scales with how many trees are actually out there, not with land you aren't using. Planted denser than that, trees genuinely compete for a shrinking footprint, so each one's share — and rainfall credit — shrinks for real, and total use levels off at the land-area ceiling rather than climbing further. Assumes roughly 80% of any given rainfall reaches the root zone.

What this does and doesn't cover. Temperature through the day, cloud cover and sun exposure all feed into ET0 as above, so yes — they matter, and they're already in the number. A genuine heatwave shows up automatically as a spike in ET0, not as a separate flag. What isn't modeled: windblown dust or sandstorms (no free weather API reports this directly) and any physical damage to the canopy — those still need a human to notice and override by hand.

Rest day. The rest day itself is never watered, but its water isn't simply lost: whatever it would have needed is split in half onto the day before (so the soil is already moist going into the dry day) and the day after (to make up the rest), so the week's total stays the same as it would without a rest day at all — only the timing changes. If the rest day would have needed nothing anyway (say it's forecast to rain), nothing is redistributed. Turning the rest day off entirely ("None") removes this step too, since every day is then watered on its own. Any day whose demand — including a redistributed share — would exceed the pump's flow rate × max hours is capped at that ceiling and flagged.

Timing. Each day's watering window is picked from the hourly forecast (early morning, evening, or late night — midday is never used) by whichever of those windows is driest, to cut evaporative loss. Without hourly data it falls back to a generic early-morning slot.

Ground sensor. Only "today's" card accepts a real sensor reading — the forecast days ahead are still estimates, and nothing can be measured for a day that's already passed. A moisture reading at or above 0.30 m³/m³ skips today's irrigation outright; below that it scales the need down proportionally. A measured evapotranspiration reading replaces the modeled estimate for today only.

Choosing dates. The calendar sets which 7-day window "this week" means. Greyed-out dates have no forecast (Open-Meteo's own live range is roughly 90 days back to 15 days ahead) — you can still pick them, but you'll enter that week's weather by hand.

Data sources. Weather, modeled soil moisture and ET0: Open-Meteo (reliable in testing). Soil type: a built-in table of named regional surveys plus global desert / Mediterranean / rainforest climate belts — this is the primary source precisely because it makes no network call and so cannot go down. ISRIC SoilGrids is offered as an optional live upgrade for extra precision, but it has proven unreliable in repeated testing (anywhere from under a second to a full timeout on the same query) and should not be relied on. Map: OpenStreetMap. If any live source can't be reached, the affected field falls back to whatever you last set by hand.
